= Elasticsearch Stack Monitoring

This recipe demonstrates how to configure Stack Monitoring for an Elasticsearch cluster by shipping metrics and logs to a dedicated monitoring cluster.

IMPORTANT: This recipe is for illustration purposes only and should not be considered production-ready.

CAUTION: This recipe uses the `node.store.allow_mmap: false` configuration value to avoid configuring memory mapping settings on the underlying host. This could have a significant performance impact on your Elasticsearch clusters and should not be used in production without careful consideration. See https://www.elastic.co/guide/en/cloud-on-k8s/current/k8s-virtual-memory.html for more information.

== Recipe

The manifest deploys two Elasticsearch clusters and a Kibana instance:

- `elasticsearch-monitoring`: the dedicated monitoring cluster that receives metrics and logs.
- `elasticsearch`: the monitored cluster, configured via `spec.monitoring` to send both metrics and logs to `elasticsearch-monitoring`.
- `kibana-monitoring`: a Kibana instance connected to the monitoring cluster, where the Stack Monitoring UI can be accessed.

[source,sh]
----
kubectl apply -f querylog-e2e-test.yaml
----

Once all pods are running, open the Stack Monitoring app in the monitoring cluster's Kibana to inspect the health and performance of the monitored cluster.

See link:https://www.elastic.co/guide/en/cloud-on-k8s/current/k8s-stack-monitoring.html[ECK Stack Monitoring documentation] for more information.
